# ISL PUM · GAME EVOLUTION TIMELINE v1

Status: LAB ONLY · SPOILER-SAFE

## Phase A — Portable game seed
Goal:
small, fun, turn-based portable RPG with square-screen readability and blind play.

Early principles:
- few controls
- pixel aesthetic
- exploration
- turn-based combat
- surprise
- portable hardware first

## Phase B — Game becomes a creative instrument
Tablet introduced as companion surface.

Added:
DRAW
SPEAK
GENERATE

Reason:
player creativity should feed the project while still feeling like play.

## Phase C — Living memory
Added:
Playtrace
Tempo
Biography
Echo

Reason:
store not only what happened, but patterns of interaction and return.

## Phase D — Cross-device handoff
R36 <-> tablet concept added.

Goals:
- play on console
- draw/speak on tablet
- return quickly
- preserve state/provenance

## Phase E — Unreal proving ground
Portable game reframed as low-cost systems lab.

Goal:
prove mechanics and data flows cheaply before expensive Unreal implementation.

## Phase F — Architecture compression
Six organs frozen:
PLAY
EXPRESS
REMEMBER
REDEFINE
ORCHESTRATE
TRANSFER

Duplicate systems merged.
Extra bots/panels parked.

## Phase G — Display correction
Second screen stopped being permanent.
Main law:
THE GAME IS ONE SCREEN.

192x192 safe square created for R36-style display.

## Phase H — Progression correction
Traditional level/xp treadmill removed.

Persistent collection compressed to:
rings
pens
lighters

Reason:
reduce cognitive load and RPG grind while keeping identity and depth.

## Phase I — Production-quality correction
Concept sprite sheets downgraded to reference-only.

Asset contract added:
concept -> mock -> in-engine -> device -> human -> production.

## Phase J — Reliability / NASA-inspired assurance
Added:
verification vs validation
fault injection
IV&V-style independent checks
STATIC/LOGIC/FAULT/EMULATOR/DEVICE/HUMAN gates.

## Phase K — Save resilience
Added:
A/B transactional journal
rollback
checksum/schema/generation
bug/recovery ledger

## Phase L — Delight capture
Added:
ME FLIPA

Purpose:
capture moments the player loves without breaking play.
Voice/photo optional.
Exports later to CSV/Sheets/PDF/backlog.

## Phase M — Multimodal expression
Separated:
what sound is present
how the person draws/speaks
what is happening in-game

Added optional, non-clinical adaptive responses.

## Phase N — Jung as playful lens
Archetypes permitted only as:
narrative/playstyle hypotheses
adaptive tone families
reversible presentation variation

Never diagnosis or personality truth.

## Phase O — 12-plane ecosystem
