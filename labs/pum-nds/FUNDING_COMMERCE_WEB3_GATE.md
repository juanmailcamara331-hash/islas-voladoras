# ISL PUM · Funding / Commerce / Web3 Gate

Status: EXPLORATORY · NO FINANCIAL PROMISES · NO TOKEN DEPLOYMENT

## Objective
Prepare optional funding/commercial rails without letting monetization distort game design.

## Order
1. Great playable proof.
2. Evidence of interest.
3. Community / mailing / wishlisting.
4. Crowdfunding economics.
5. Commerce / fulfillment.
6. Only then evaluate blockchain utility.

## Kickstarter
Prepare:
- clear project story;
- realistic minimum budget;
- reward fulfillment model;
- update cadence;
- delivery risks;
- tax/shipping assumptions;
- prototype evidence.

Kickstarter remains separate from ISL canon and game balance.

## Commerce
Candidate stack:
- Shopify for physical/digital catalog;
- Stripe-class payment rails;
- inventory/fulfillment integrations;
- analytics.

## Blockchain / NFT / token
Do NOT deploy by default.

Possible legitimate uses to evaluate:
- provenance certificate for limited physical art/relics;
- optional collector record;
- non-transferable participation badge;
- experimental interoperable ownership record.

Avoid:
- pay-to-win;
- investment promises;
- artificial scarcity as core gameplay;
- token-price dependence;
- liquidity pool before legal/economic review.

Before any public token/NFT launch:
LEGAL REVIEW
-> MiCA classification
-> consumer/tax review
-> technical security audit
-> utility rationale
-> treasury/key management
-> disclosure/risk document
-> HUMAN GO

## Research angle
Web3 may be studied as one provenance mechanism among alternatives.
Do not assume blockchain is superior to signed hashes / normal databases.
