# ISL PUM · Dialectical Consolidation v1

Status: LAB ONLY · SPOILER-SAFE · NO AUTO-CANON

## Thesis
We built a portable RPG probe with:
- minimal controls;
- touch/gesture;
- optional voice;
- cross-device handoff;
- save/playtrace;
- encounter redefinition;
- Serendipinator/Orchestrator;
- compact creative panel;
- Unreal handoff;
- research provenance.

## Antithesis
Too many documents/layers risk:
- duplicated concepts;
- too many names;
- too much meta-interface;
- player instrumentation becoming visible;
- context controls becoming inconsistent;
- "AI interpretation" outrunning evidence;
- sync becoming more important than play;
- creative panel competing with the RPG.

## Synthesis: six organs only

### 1. PLAY
Movement, turn-based RPG, encounters, exploration.
Must remain immediately understandable.

### 2. EXPRESS
Gesture/drawing + optional voice + contextual input.
No diagnostic claims.
No extra permanent buttons.

### 3. REMEMBER
Save + Playtrace + object/relation biography.
One memory system, not separate telemetry systems.

### 4. REDEFINE
Encounter Question:
"What can this do now that it has met that?"
PIM/PAM/PUM are surface verbs of the same redefinition engine.

### 5. ORCHESTRATE
Serendipinator proposes.
Orchestrator integrates.
Manera constrains identity.
Human Gate decides.
These are distinct roles but one pipeline.

### 6. TRANSFER
R36 <-> tablet <-> Unreal <-> research/creative tools.
One neutral event/data language.

Everything else is UI, infrastructure, research, or distribution around these six.

## New transversal mechanic: TEMPO

Not a mood detector.
Not a personality score.

TEMPO is an observable play-state variable derived from:
- action cadence;
- hesitation;
- gesture speed/curvature;
- repeated inputs;
- optional acoustic rhythm/energy;
- exploration/combat pacing.

TEMPO may influence only bounded presentation/system parameters:
- animation pacing;
- transition speed;
- response windows;
- density of optional prompts;
- music layer intensity;
- frequency of serendipity opportunities;
- panel animation rhythm.

TEMPO never changes core difficulty or story authority by itself.
Large changes require corroborating play history + reversible branch + Human/Design rules.

Why it matters:
One variable lets gesture, voice, controls, sound, UI and playtrace speak the same language without pretending to know psychology.

## New transversal mechanic: OBJECT BIOGRAPHY

Every meaningful object/entity may carry:
- origin;
- encounters;
- transformations;
- gifts/transfers;
- uses;
- failures;
- returns;
- redefinitions.

The player does not see the full ledger.
The world can react to accumulated biography.

This unifies:
collecting
+ boxes
+ gifts
+ family contributions
+ relation memory
+ redefinition
+ future Unreal data assets.

## New transversal mechanic: ECHO

A past action can return later in a different system.

Rule:
An ECHO must preserve provenance.
It is not random callback.

Examples at system level:
gesture -> later UI rhythm
object history -> later relation option
drawing feature -> later visual motif
voice rhythm -> later timing pattern
family contribution -> later non-spoiler world response

No content-specific examples in public/player docs.

## Control law
Core permanent actions remain few.

Do not add a button for:
TEMPO
ECHO
REDEFINE
SERENDIPITY
PLAYTRACE

They happen through normal play.

Rear triggers remain modifiers, not features.

## One cockpit

PLAY MODE:
almost invisible.
Only what is needed now.

REVIEW MODE:
after/between sessions.
Shows:
- current circulation;
- candidate branches;
- notable echoes;
- transfer readiness;
- build/sync health.

No spoiler content.
No fake psychological labels.

## Unreal training target
Every system must have:
1. semantic input;
2. neutral state;
3. deterministic/replayable consequence where practical;
4. save representation;
5. test;
6. Unreal mapping.

If it cannot cross this bridge, it stays experimental.

## Final quality equation

VALUE =
FUN
x CLARITY
x MEMORY
x REDEFINITION
x TRANSFERABILITY

SERENDIPITY is a multiplier, not the base.

If FUN or CLARITY approaches zero, cleverness does not save the feature.
