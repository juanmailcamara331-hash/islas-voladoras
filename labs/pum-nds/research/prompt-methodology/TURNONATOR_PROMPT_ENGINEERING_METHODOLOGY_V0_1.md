# TURNONATOR · PROMPT ENGINEERING METHODOLOGY V0.1

STATUS: REUSABLE METHODOLOGY · HUMAN-GATED · CROSS-PROJECT ABSTRACT ONLY

## PURPOSE
Document the method used to build high-power continuity prompts without flattening the project's spirit, identity, provenance, or human authority.

## CORE PRINCIPLE
A master prompt should not be a dump of context.

It should act as:
- boundary;
- memory scaffold;
- routing layer;
- creative amplifier;
- safety/integrity layer;
- execution contract.

## METHOD

### 1. RECOVER
Recover:
- active human intent;
- root phrases;
- current project boundary;
- important metaphors;
- working laws;
- active experiments;
- parked branches;
- human gates;
- emotional tone;
- current artifacts.

### 2. SEPARATE
Keep distinct:
- identity;
- methodology;
- evidence;
- hypothesis;
- metaphor;
- joke;
- canon;
- lab material.

### 3. ABSTRACT BEFORE CROSSING PROJECTS
For any external project:

SOURCE
→ ABSTRACT FUNCTION
→ REMOVE IDENTITY
→ TRANSLATE
→ COMPATIBILITY TEST
→ SMALL TEST
→ HUMAN VERDICT.

Rule:
READ != ADOPT
OBSERVE != COPY
COMPARE != MERGE
ABSTRACT != ERASE PROVENANCE

### 4. PRESERVE SOUL
Before adding any framework, ask:
Does this improve:
- creativity?
- clarity?
- play?
- agency?
- beauty?
- naturality?
- traceability?
- useful surprise?

If not:
PARK / KILL.

### 5. USE THREE LANGUAGES
Every important construct should be expressible in:
A. natural / street language
B. functional / operational language
C. academic / evidence-aware language

None replaces the others.

### 6. BUILD A BOOT, NOT A BIBLE
The prompt should:
- activate the right context;
- route work;
- protect boundaries;
- trigger action.

It should NOT:
- force every concept into every turn;
- repeat the whole history;
- create bureaucracy.

### 7. FIRST-TURN CONTRACT
A master prompt should end with a concrete first mission.

Preferred:
- one visual/graph;
- one build;
- one experiment;
- one research hypothesis;
- one artifact;
- one delta.

Avoid:
"Please summarize the prompt."

### 8. HUMAN-GATE DESIGN
Safe autonomous work:
- research;
- comparison;
- reversible docs;
- prototypes;
- prompts;
- local code;
- visual studies;
- experiments.

Human approval:
- canon;
- spending;
- publishing;
- external communication;
- irreversible changes;
- sensitive decisions.

### 9. ANTI-META RULE
META → ACTION within one turn when safe.

If three consecutive layers of theory appear with no artifact:
FORCE ONE SMALL BUILD.

### 10. CONTINUITY
Every important master prompt should have:
- VERSION;
- DATE;
- STATUS;
- SCOPE;
- AUTHORITY;
- ROOT PHRASES;
- CURRENT POINTER;
- NEXT ACTION.

## QUALITY TEST
A good continuity prompt should pass five tests:

1. If read in a new chat, does it recover direction quickly?
2. Can it produce useful work without asking twenty questions?
3. Does it preserve what belongs to the human?
4. Can it absorb new information without rewriting history?
5. Can it stop itself from turning into bureaucracy?

## WORKING NAME
TURNONATOR = prompt architecture that turns on the right creative/research organism without importing the whole universe blindly.

## ROOT LAW
PROMPT != CONTENT DUMP.
PROMPT = BOUNDARY + ROUTER + MEMORY SCAFFOLD + CREATIVE IGNITION + HUMAN GATE.
