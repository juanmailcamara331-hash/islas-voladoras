## 2 · Core player loop

-> ENCOUNTER
-> TURN-BASED RPG ACTION
-> OPTIONAL SHIP-COMBAT LANE
-> RECOVER / CONTINUE
-> DISCOVER

-> RETURN DIFFERENT

Primary persistent collection families:
- rings
- pens
- lighters

These may alter derived play/presentation properties without creating inventory bloat.

## 3 · Main control law
Few semantic actions, contextual meanings.

Permanent semantic inputs:
MOVE
PRIMARY
SECONDARY
CONTEXT
CANCEL/MENU

Auxiliary/screen swap belongs to emulator/device profile, not core game controls.

Progressive disclosure:
MOVE
-> PRIMARY
-> SECONDARY
-> CONTEXT
-> AUX/TABLET only when a task materially benefits.

## 4 · Display law
THE GAME IS ONE SCREEN.

Critical composition lives inside a centered 192x192 SAFE_SQUARE.

Second DS screen:
BLACK / QUIET / UNUSED by default.

Only activate for:
- touch
- drawing
- bounded contextual interaction
- tablet-style companion task

Then return immediately to single-screen play.

## 5 · Tablet companion
Tablet is not a dashboard that stays open.
It appears briefly when needed.

Actions:
DRAW
SPEAK
GENERATE
ME FLIPA

DRAW:
captures observable drawing features.

SPEAK:
captures transcript and observable voice features.

GENERATE:
routes to the cheapest suitable service or prepare/open workflow.

ME FLIPA:
one-tap delight capture with optional voice/photo, then immediate return to play.

## 6 · Multimodal expression
Three layers:

L1 SOURCE CLASSIFICATION
what sound/event is present.

L2 EXPRESSIVE FEATURES
voice/drawing rhythm, duration, speed, pauses, curvature, revisions, etc.

L3 GAME CONTEXT
what was happening in the game.

Rule:
AI notices patterns.
The game proposes.
The Orchestrator contextualizes.
The player decides whether it works.

No diagnosis.
No intelligence inference.
No hidden-intent inference.

Jungian archetypes may be used only as optional narrative/playstyle lenses.
