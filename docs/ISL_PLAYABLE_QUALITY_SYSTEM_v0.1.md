# ISL — PLAYABLE QUALITY SYSTEM v0.1
Estado: PROVISIONAL FUERTE · ISL ONLY · NO CANON AUTOMÁTICO
Fecha: 2026-09-21

## FUENTES INTERNAS DE AUTORIDAD
Derivado de la metodología ya consolidada en ISL:
- Experience Card: PROMESA → ATENCIÓN → ACCIÓN → FEEDBACK → SORPRESA → APRENDIZAJE → TRANSFORMACIÓN → PAYOFF → RECUERDO.
- Presupuesto de atención.
- Build de la Verdad: mínimo contenido × máxima identidad demostrable.
- CQC-R: CONSTRUIR → CQC → CORREGIR → CRUZAR → CQC → CERRAR.
- Regla 1–3–∞: una prueba mínima, hasta tres conexiones iniciales, expansión sólo después de demostrar valor.
- Δ = transformación perceptible a través del tiempo.
- Build Science: CAPABILITY + REGRESSION, escalera T0–T8.
- Game feel stack: input → locomoción → cámara → animación → audio/VFX → sensación.

## NO INVENTAR UNA NOTA MÁGICA
La Biblia dice expresamente que la antigua suma ponderada no es una fórmula final.
Por tanto, este sistema NO produce un “92/100 magistral” falso.

## ECUACIÓN OPERATIVA PROVISIONAL DE PUERTA
Q_PLAY = min(C, A, F, D, R)

donde cada término sólo puede considerarse alto con evidencia humana:
- C = claridad: entiendo qué puedo hacer y por qué.
- A = agencia: mi acción cambia algo perceptible.
- F = feel: tocar/controlar produce respuesta satisfactoria.
- D = deseo: me apetece continuar/repetir.
- R = robustez: móvil/web/app no rompe navegación, audio, viewport, estado o retorno.

Uso: weakest-link gate. Si un componente falla, no se compensa decorando los demás.
NO ES CANON matemático; es un operador de decisión de producción.

## REGLA Δ
Todo jugable debe producir al menos una transformación perceptible:
acción del jugador → cambio visible/sonoro/sistémico → nueva lectura o posibilidad.
Sin Δ, el prototipo puede ser bonito pero no demuestra juego.

## PUERTA DE ATENCIÓN
Antes del primer input relevante:
- una sola acción primaria;
- máximo tres ideas nuevas visibles;
- el resto se revela después.
Si hace falta explicar mucho antes de jugar, rediseñar la entrada.

## SUITE POR JUGABLE
### T0 STATIC
- carga;
- enlaces válidos;
- viewport;
- sin shell privado accidental;
- assets presentes.

### T1 CAPABILITY
- acción núcleo responde;
- feedback inmediato;
- estado cambia.

### T2 SMOKE
- inicio → núcleo → final → retorno sin atasco.

### T3 INTEGRATION
- fullscreen/audio/save/navigation no interfieren.

### T4 CONTENT STRESS
- repetir, tocar rápido, volver atrás, recargar, rotar.

### T5 VISUAL
- móvil vertical/horizontal;
- jerarquía legible;
- sin franjas/huecos/blur/superposición.

### T6 PACKAGED
- Android APK física.

### T7 REGRESSION
- bugs conocidos no reaparecen.

### T8 HUMAN / CQC
Preguntas mínimas:
1. ¿Entendiste qué pasaba?
2. ¿Te divertiste?
3. ¿Seguirías?
+ comentario opcional.

## STOP RULE
Otra vuelta de CQC sólo se hace si:
- cambia una decisión;
- descubre una regresión;
- mejora perceptiblemente C/A/F/D/R.
Si no, parar y probar con persona real.
