# ISL · CREATIVE MOMENTUM & ARTIFACT LOOP CURRENT
Fecha: 2026-09-21
Estado: ACTIVE METHOD · ISL ONLY

## POR QUÉ EXISTE
La sesión creativa de hoy mostró un patrón valioso:
crear assets/entes visibles, recibir una respuesta inmediata, compararlos con referencias, materializarlos y sentir progreso tangible aumenta energía, inspiración y deseo de continuar.

Esto NO se interpreta como “gamificación para exprimir productividad”.
Se usa para proteger disfrute, sorpresa, agencia humana y continuidad creativa.

## PRINCIPIO DE DOPAMINA SANA
El sistema puede usar:
- sorpresa;
- progreso visible;
- pequeños cierres;
- artefactos reales;
- desbloqueo de la siguiente pieza;
- reconocimiento humano;
- celebración.

No usar:
- culpa;
- streaks coercitivos;
- urgencia falsa;
- recompensas que sustituyen juicio;
- métricas para presionar;
- notificaciones constantes.

## REWARD = ARTIFACT
La recompensa preferida es que exista algo:
- una imagen buena;
- un objeto;
- un prototipo;
- una escena;
- un PDF;
- una pieza física;
- una decisión clara;
- una mejora que se puede enseñar.

## REFERENCE SPARK
Las referencias funcionan como chispa, no como jaula:
SOURCE_OF_TRUTH → comparación → diferencia → mutación ISL → validación.

Si un ente ya está aprobado:
DERIVE / EDIT / VECTORIZE / TECHNICALIZE.
No regenerar desde cero.

## ENTITY MEMORY
Cada nuevo hito visible debe consultar:
- qué entes ya existen;
- cuál está aprobado;
- qué está bloqueado;
- qué se puede variar;
- cuál es la siguiente transformación útil.

Esto evita que la energía creativa produzca duplicados o contaminación contextual.

## SOCIAL / HUMAN LOOP
Cuando tiene sentido:
CREAR → HACER PARTÍCIPE → OBSERVAR → AGRADECER → MATERIALIZAR → DEVOLVER AL MUNDO.

Participación humana no es input extractivo.
Debe cerrar el círculo con gratitud, memoria o artefacto cuando corresponda.

## SESSION SHAPE
### ARRANQUE
- recordar de dónde venimos;
- mostrar una sola siguiente pieza;
- abrir permiso de color.

### FLOW
- generar / editar;
- enseñar;
- reacción humana rápida;
- conservar / mutar / descartar;
- registrar ente.

### CIERRE
- ¿qué hicimos real?
- ¿qué aprendimos?
- ¿qué queda aprobado?
- ¿qué queda superseded?
- ¿cuál es la única siguiente acción agradable?
- persistir Drive/GitHub si es significativo.

## CONTEXT HYGIENE
Usar mini-reset:
TASK ANCHOR → ENTE → OPERATION → SOURCE_OF_TRUTH → LOCKED/MUTABLE → EXECUTE → VERIFY → REGISTER.

No hace falta nueva conversación hasta:
- checkpoint;
- cambio de bloque;
- cambio de PRIMARY;
- contexto realmente confuso.

## NOTIFICATION PHILOSOPHY
Las notificaciones sólo deben aparecer cuando:
- hay algo que celebrar;
- una decisión desbloquea trabajo;
- una muestra/test llegó;
- conviene recordar volver a una pieza concreta.

No mandar “trabaja más”.
Mandar “mira lo que ya existe y elige si te apetece tocar la siguiente pieza”.
