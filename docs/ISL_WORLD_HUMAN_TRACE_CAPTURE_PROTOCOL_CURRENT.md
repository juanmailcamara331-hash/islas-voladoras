# ISL_WORLD_HUMAN_TRACE_CAPTURE_PROTOCOL_CURRENT

Estado: CANON METODOLÓGICO · ISL ONLY
Fecha: 2026-09-21

## PROPÓSITO
Convertir vivencias reales, personas, hazañas, accidentes fértiles, conversaciones, feedback y señales humanas en materia creativa útil para ISL sin copiar vidas privadas ni desviar el PRIMARY.

## DISPARADOR
Cuando aparezca una experiencia humana con carga emocional, física, social, cómica, contradictoria o memorable, activar:

REALIDAD → HUELLA → DESIDENTIFICACIÓN → FUNCIÓN → CONTRADICCIÓN → MUTACIÓN ISL → CRUCE SISTÉMICO → CQC-R → EVIDENCIA HUMANA → DECISIÓN.

## QUÉ PUEDE ENTRAR
- vivencias del autor;
- acciones/hazañas;
- encuentros con desconocidos;
- conversaciones con familia/colegas/testers;
- gestos, errores, sorpresas, tensiones y cuidados;
- frases espontáneas;
- reacciones humanas a ISL;
- observaciones de mundo real.

## PERSONAS
Las personas reales NO se convierten automáticamente en personajes.
Extraer función humana, tensión, gesto, relación o ritmo.
Desidentificar por defecto.
No conservar datos sensibles innecesarios.
No usar historias de terceros de forma reconocible sin consentimiento adecuado.

## HAZAÑAS
Una hazaña no se registra como premio moral.
Se analiza por:
- esfuerzo;
- coste;
- riesgo;
- contradicción;
- cooperación;
- cuidado;
- fallo;
- consecuencia;
- recuerdo.

## CRUCE
Cada huella puede cruzarse con máximo 1–3 sistemas existentes:
mundo, vínculos, Brújula/Huellas, reliquias, tripulación, humor, memoria, navegación, escenas, criaturas.
No abrir un sistema núcleo nuevo sólo para alojarla.

## CLASIFICACIÓN
- TRACE_RAW: captura privada/desidentificada.
- SEED: semilla creativa.
- COLOR_LANE: puede alimentar una microadición sin desviar PRIMARY.
- PROTOTYPE_CANDIDATE: merece prueba barata.
- CANON_CANDIDATE: sólo tras CQC-R + evidencia + decisión humana.
- PARK / KILL.

## BOT / RECORDATORIO DE PROCESO
En todo bloque significativo de ISL preguntar:
1. ¿ha ocurrido alguna huella humana nueva?
2. ¿hay persona/hazaña/feedback que merezca captura?
3. ¿está desidentificado?
4. ¿qué función aporta?
5. ¿qué contradicción abre?
6. ¿qué 1–3 sistemas cruza?
7. ¿cambia una decisión o sólo añade ruido?
8. ¿debe quedar en SEED/COLOR/PARK?
9. ¿requiere consentimiento o protección adicional?
10. ¿debe actualizar checkpoint/pointer?

## GUARD
Capturar no equivale a producir.
Producir no equivale a CANON.
La huella nunca puede desplazar un gate humano activo ni romper el foco del PRIMARY.

## HUMAN CHARACTER SOURCE METHOD · 2026-09-28
Estado: ACTIVE METHOD · PRIVATE-BY-DEFAULT · NO NEW ORGAN · NO AUTO-CANON

Propósito:
usar amigos, conocidos y relaciones reales como materia humana para NPCs, companions, tripulación y secundarios sin copiar una persona real de forma automática ni convertir una cara en diagnóstico.

Flujo:
PERSONA REAL
→ OBSERVACIÓN / RECUERDO / FOTO CONSENTIDA
→ CONDUCTA OBSERVABLE
→ RELACIÓN
→ CONTRADICCIÓN
→ GESTO / RITMO / VOZ FUNCIONAL
→ NÚCLEO EMOCIONAL
→ DISTANCIA D2–D4
→ CHARACTER GRAMMAR
→ MUTACIÓN ISL
→ MICROSCENE / CHEAP TEST
→ HUMAN READ
→ KEEP / MUTATE / PARK / KILL
→ HUMAN CANON REVIEW si algún día procede.

Principios:
- PERSONA REAL = SOURCE; NPC FINAL ≠ PERSONA REAL.
- FOTO = ancla visual de postura, ropa, materialidad, contexto y gesto visible; nunca inferir salud, trauma, ideología, orientación, inteligencia o personalidad desde la cara.
- CARÁCTER = experiencia humana aportada + conducta observable + relación; no lista de adjetivos.
- Preferir DESEO + COSTUMBRE + CONTRADICCIÓN + UMBRAL + RELACIÓN + CAMBIO.
- La misma frase, gesto o hábito puede significar cosas distintas según contexto; conservar ambigüedad cuando sea humana.
- Una contradicción no necesita explicación traumática.
- No todos los personajes deben ser simpáticos, redimirse o tener arco terapéutico.
- La ropa puede ser gramática de estado/contexto, no uniforme psicológico.
- El vínculo puede crecer mediante HACER JUNTOS, SILENCIO, RUTINA, HUMOR, TRABAJO o CUIDADO; no depender por defecto de barras de afinidad o respuestas correctas.
- Mezclar rasgos de varias fuentes puede mejorar ficción, privacidad y distancia.
- Publicación de nombre, rostro, voz, frases privadas o anécdotas reconocibles requiere consentimiento adecuado.

Ficha mínima recomendada:
- source_alias_private
- visible_anchors
- observed_behaviours
- relationship_context
- thesis
- antithesis
- living_contradictions[]
- comfort_state
- friction_state
- absurdity_or_play_valve
- care_or_creation_mode
- boundary_or_threshold
- speech_grammar
- clothing_grammar
- emotional_core
- transformation_distance
- literal_details_to_remove[]
- transferable_functions[]
- candidate_game_roles[]
- relationship_arc_candidate
- micro_scene_test
- privacy_risk
- consent_requirement
- human_read
- canon_status

Regla de calidad:
Si la ficha sólo contiene adjetivos, NO está lista.
Debe contener al menos una conducta, una contradicción, una relación y una escena o situación observable.

Regla de juego:
CHARACTER DEPTH > BIOGRAPHICAL LORE.
El jugador debería poder conocer a alguien por cómo actúa, cambia, recuerda y responde, no porque un dossier lo explique.

Cruces permitidos:
máximo 1–3 por mutación: tripulación · vínculos · Huellas · diálogo · rutina · combate · creación · mundo · humor · navegación · reliquias.

Guard:
No desplaza PRIMARY.
No crea un sistema social nuevo por sí solo.
No convierte Human Lab en requisito de producción.
