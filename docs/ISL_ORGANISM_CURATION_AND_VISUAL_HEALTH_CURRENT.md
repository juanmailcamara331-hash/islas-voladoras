# ISL · ORGANISM CURATION + VISUAL HEALTH · CURRENT
Fecha: 2026-09-23
Estado: ACTIVE · TRANSVERSAL · ADDITIVE · NO NEW ORGAN

## PURPOSE
Keep ISL's living organism healthy over time by curing redundancy, dead text, duplicated authority, toxic cross-links, stale prompts, hidden contradictions and visual overload without deleting history or flattening identity.

Core rule:
DO NOT ADD ORGANS. IMPROVE CIRCULATION.
DO NOT DELETE MEMORY. PRUNE ACTIVE AUTHORITY.
DO NOT COMPRESS SO HARD THAT SOUL / HEART / SKIN / CONTEXT DISAPPEAR.

## 1. CURATION LOOP
Use periodically and at major milestones:

SCAN
→ MAP CONNECTIONS
→ DETECT REDUNDANCY / TOXICITY
→ CLASSIFY
→ PRUNE ACTIVE AUTHORITY
→ MERGE / LINK / ARCHIVE
→ RECHECK ORGANISM
→ HUMAN READ IF IDENTITY-AFFECTING
→ RETURN HOME

Classifications:
KEEP ACTIVE
MERGE
LINK ONLY
ARCHIVE
SUPERSEDED
CONFLICT / TEST_REQUIRED
PARK
DELETE ONLY IF SAFE NON-HISTORICAL DUPLICATE

## 2. WHAT TO CURATE
- boot docs;
- CURRENT docs;
- automation prompts;
- pointer/checkpoint overlap;
- repeated guards;
- dead reminders;
- stale references;
- duplicated visual authority claims;
- redundant methodology prose;
- cross-project contamination;
- contradictory gates;
- obsolete UI instructions;
- hidden dependencies that only exist in chat memory;
- overgrown matrices that no longer change decisions.

## 3. TOXIC REDUNDANCY TEST
A repeated rule becomes toxic when it:
- creates conflicting wording/authority;
- makes boots slower without reducing uncertainty;
- hides the real human lock inside boilerplate;
- causes the assistant to overfit to process instead of the work;
- causes every generation to carry unnecessary constraints;
- duplicates a stronger source without adding nuance;
- keeps old assumptions alive after they were superseded.

Do not remove repetition that is intentionally acting as a safety/authority guard unless a stronger single source clearly replaces it.

## 4. HEALTH QUESTIONS
For each organ / surface:
- Is its function still clear?
- Is there one obvious authority source?
- Are inputs/outputs legible?
- Is it overfed by references?
- Is it starving for evidence?
- Is it duplicating another organ?
- Is it leaking internal complexity into human/player surfaces?
- Does it still preserve soul / heart / humanity?
- Is the skin hiding a weak heart?
- Is the organism spending energy remembering things that no longer matter?

## 5. ORGANISM HEALTH VISUALIZATION
The internal Organismo Vivo screen should become an interactive map of project health.

Preferred interaction:
- hover = 1-line explanation;
- click/tap = floating card;
- long/expanded view = evidence, linked docs, current gate, next test;
- sliders only for meaningful dimensions;
- diagrams only where they clarify flow;
- heatmaps only for internal health/coverage/risk, never decorative noise.

Suggested dimensions:
AUTHORITY
EVIDENCE
HEART / HUMANITY
PLAYABILITY
VISUAL IDENTITY
CIRCULATION
RISK
READINESS
REFERENCE DISTANCE
MEMORY / PROVENANCE

Suggested semantic scale:
GREEN = healthy / evidenced / aligned
AMBER = direction exists / test pending
RED = blocked / conflict / missing authority
BLUE = exploratory / lab
VIOLET = PRISM / high-entropy research
GREY = archive / inactive / historical

Color is never sufficient alone: pair with icon/text/pattern for accessibility.

## 6. TYPOGRAPHIC / SIZE LANGUAGE
Size and typographic weight may encode importance, but never as the only signal.

Internal control surfaces:
- larger = more current/structural/urgent;
- smaller = supporting/context/archive;
- weight = authority/importance;
- density = evidence or complexity;
- spacing = separation between organs/functions.

Player-facing UI:
use this language sparingly.
Minimal HUD still governs.
Do not turn gameplay into a dashboard.

## 7. WORD MOSAICS / SEMANTIC CLOUDS
Allowed internally for:
- current themes;
- unresolved tensions;
- reference functions;
- human feedback;
- recurring words from tests;
- memory/identity clusters.

Rules:
- never replace source evidence;
- never infer psychological truth from frequency;
- never become decorative noise;
- show provenance / sample where meaningful;
- use as orientation sensor, not authority.

## 8. MENUS / HUD / ENTITIES CROSS
Reuse the organism's visual grammar in the game only through distilled principles:
- semantic color families;
- relative scale;
- breathing room;
- hierarchy;
- subtle pulse/animation;
- diegetic material cues;
- local heat/intensity when functionally meaningful.

Do NOT transplant:
- project-health heatmaps;
- authority grades;
- internal sliders;
- debug language;
- process labels.

Player UI must inherit FEEL, not internal machinery.

## 9. GENERATION / BULLET USE
Before a major generation:
- read current organ health only for relevant organs;
- inherit 2–4 strongest locks;
- inherit one risk;
- inherit one unresolved question;
- do not dump the whole organism into every prompt.

After generation:
- update only organs actually affected;
- avoid global propagation from one pretty result;
- record evidence/provenance if meaningful.

## 10. PERIODIC CURATION
Cadence:
light monthly curation by existing automation;
major curation at:
- checkpoint accumulation;
- authority conflict;
- new lifecycle stage;
- major public/demo milestone;
- 3+ structural changes;
- when boots become slow/noisy/conflicting.

Maximum automatic action:
ONE reversible simplification per pass unless P0 safety/authority incident.

## 11. MACHINE MINIMALISM
Automations and docs should act like a nervous system, not bureaucracy.

Prefer:
event trigger;
single source;
link/reference;
small reversible update;
silent healthy state.

Avoid:
new bot for every concern;
duplicate reminder;
parallel truth;
full re-read of entire project every time;
global regeneration;
process theatre.

## 12. PRINCIPLE
HEALTHY ISL = strong heart + clear spine + living skin + enough memory + low bureaucratic inflammation.

The system should feel conscious enough to remember, unconscious enough not to interrupt, and entropic enough to keep discovering.
