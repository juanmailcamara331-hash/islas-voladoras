# ISL — DD GLOBAL ECOSYSTEM MATRIX v0.22
Fecha: 2026-09-18
Estado: ACTIVO / ESTRATEGIA TRANSVERSAL

## PRINCIPIO
DD = Discoverability + Distribution + Community + Funding + Press + Creator Relations.

No existe "marketing al final".
Cada artefacto ISL debe saber:
- para quién existe;
- qué problema/curiosidad resuelve;
- dónde puede descubrirse;
- qué acción siguiente propone;
- cómo vuelve al universo ISL.

## ROLES DE PLATAFORMA

### TIER A — columna vertebral
**Sitio propio / Netlify**
Rol: fuente canónica, SEO, lore indexable, enlaces, press kit, demos, mailing.
Gate: activo ya.

**YouTube / YouTube Music**
Rol: música, visualizers, reels, devlogs visuales, búsquedas long-tail, playlists.
Gate: activo cuando derechos/CQC de cada pieza estén verificados.

**Steam**
Rol: wishlist, demo, playtest, Next Fest, lanzamiento PC, reviews.
Gate: página pública sólo cuando posicionamiento, cápsulas de tienda y primer trailer representen el juego real.
Nota: Next Fest sólo una vez; elegir edición estratégicamente.

**Email propio**
Rol: audiencia portable y no dependiente del algoritmo.
Preferencia inicial: herramienta ligera con exportación fácil.
Gate: activar antes de crowdfunding o página Steam pública fuerte.

**Discord**
Rol: núcleo de comunidad, playtests, insiders, feedback.
Gate: abrir cuando exista una razón concreta para volver cada semana; evitar servidor vacío.

### TIER B — aceleradores
**Kickstarter**
Rol: financiación + validación + comunidad.
Modelo: all-or-nothing; 5% de plataforma si financia + procesamiento.
Gate: vertical slice jugable, presupuesto real, calendario, recompensas, fulfillment y base de audiencia preexistente.
KPI central ISL: backers y relación, no sólo euros.

**BackerKit**
Rol: crowdfunding, mailing, pledge management, late pledges.
Fit: fuerte si ISL llega con base de fans y logística/recompensas más complejas.

**Gamefound**
Rol: crowdfunding + pledge manager; acepta Video Games y usa tags/thumbnail/cover/social image.
Fit: EXPERIMENTO; comparar audiencia real antes de elegir frente a Kickstarter.

**itch.io**
Rol: builds experimentales, demos, bundles, devlogs, nichos indie.
Gate: usar cuando una build aporte valor y esté claramente etiquetada.

**Reddit**
Rol: conversación distribuida, descubrimiento por intereses, feedback.
Regla: aportar valor nativo al subreddit; nunca spray de enlaces.

**Creadores / prensa — Keymailer, Lurkit, Woovit, PressEngine/alternativas**
Rol: códigos, campañas con creadores, coverage.
Gate: demo suficientemente buena para que un creador pueda producir contenido sin necesitar explicación.

### TIER C — regionales / especializados
**Verkami — España/cultura**
Fit: fuerte si priorizamos comunidad española y acompañamiento cultural.
Coste publicado: 5% + gestión pagos 1.5%, más IVA aplicable; todo-o-nada.

**Ulule — Europa**
Fit: campaña cultural europea/multilingüe.
Reward crowdfunding con modelo success-based y asesoramiento.

**Goteo — España / comunes**
Fit: sólo si una parte del proyecto adopta genuinamente lógica abierta/común/impacto; no forzar.

**Pozible — Australia/Oceanía**
Fit: sólo con audiencia/local partner relevante.

**CAMPFIRE — Japón**
Fit: sólo con localización, socio o comunidad japonesa probada. Coste significativamente mayor que opciones occidentales.

**Indiegogo**
Fit: radar secundario; considerar por flexible funding o audiencias concretas, no por inercia.

**Patreon**
Rol: membresía recurrente + productos puntuales.
Fit: más adelante si hay cadencia estable de cápsulas, música, making-of o builds.
Nuevos creadores: plan estándar 10% + processing.

**Ko-fi / Buy Me a Coffee**
Rol: apoyo liviano, tips, pequeñas ventas.
Fit: más simple que membresía formal; Buy Me a Coffee publica 5% de plataforma.

**Substack / beehiiv / MailerLite**
Rol: newsletter, audiencia propia, publicaciones largas.
Regla: no duplicar ecosistemas. Elegir UNA herramienta principal.
Observación 2026:
- beehiiv: plan Launch hasta 2.500 suscriptores.
- MailerLite: free actual hasta 250 suscriptores y 2.500 emails/mes.
- Substack: publicación gratis, 10% en suscripciones pagadas.

### TIER D — bases de datos / long tail
IGDB, RAWG, ModDB, Game Jolt, directorios indie, wikis y bases relevantes.
Rol: presencia estructurada y backlinks/contexto.
Gate: cuando exista página pública estable y assets definitivos suficientes.

## CROWDFUNDING GATE ISL
CF-00 necesidad real de financiación
CF-10 coste de producción y mínimo viable
CF-20 base de audiencia / mailing / comunidad
CF-30 plataforma A/B fit
CF-40 página + trailer + demo + rewards
CF-50 fulfillment/tax/legal stress test
CF-60 prelaunch / followers
CF-70 launch
CF-80 updates + community
CF-90 fulfillment + postmortem

No CF-20 PASS => no campaña.

## EVIDENCIA
- Kickstarter Creator Handbook: historia, rewards, updates, promoción y comunicación con backers.
- Steam Next Fest: demo pública + store page; sólo una participación.
- Discord recomienda empezar comunidad temprano, pero para nutrir relaciones/playtests concretos.
- Investigación en videojuegos Kickstarter: número de backers/comunidad predice mejor el éxito posterior que el dinero recaudado.
- Literatura crowdfunding: éxito depende de una combinación de calidad, señales del creador, interacción, diseño de campaña y modelo elegido; no hay una variable mágica.
- Estudio Kickstarter+Steam: reward type/claridad importa; demasiados tiers y campañas más largas pueden perjudicar.

## OLYMPUS RULE
Añadir una plataforma sólo si:
1. trae una audiencia distinta;
2. reduce trabajo/repetición;
3. mejora evidencia;
4. desbloquea financiación/distribución real;
5. o simplifica fulfillment/handoff.

Si no cumple al menos una: RADAR, no integración.
