# ISL — DD RETROFIT AUDIT OF EXISTING WORK v0.22

Estado: PRIMER PASE COMPLETADO

## OBJETIVO
Someter lo ya construido a DD sin destruir trabajo bueno ni convertir todo en marketing.

Clasificación:
KEEP = ya sirve.
TUNE = sirve con ajuste.
PROTOTYPE = probar antes de consolidar.
DEFER = correcto pero no ahora.
CUT = ruido/coste sin retorno.

## 1. IDENTIDAD / TONO / LORE
Estado: KEEP.
Fortaleza: ADN verbal y visual distintivo, humor, oscuridad, hogar, cielo, memoria.
DD gap: falta vocabulario público estable ES/EN y taxonomía de entidades.
Acción: crear lexicon público controlado: ISL, Islas Voladoras, airship home, floating islands, wind system, Separation, Velaria, etc.

## 2. COMMAND CENTER / PS4
Estado: KEEP + TUNE.
Fortaleza: showroom interno excelente.
Gap: no debe ser nuestra landing SEO principal.
Acción: separar claramente CONTROL INTERNO de PUBLIC DISCOVERY.
PS4/Recreo permanece experiencia de autor.

## 3. REEL / GALERÍA / VISUALES
Estado: KEEP + TUNE.
Gap: assets sin paquete sistemático ALT/title/caption/OG/schema/rights/provenance.
Acción: todo asset aprobado recibe metadata DD.

## 4. CÁPSULAS ISL
Estado: KEEP.
DD oportunidad: alto.
Acción: algunas cápsulas pueden convertirse en unidades públicas reutilizables:
- página indexable;
- Short/Reel;
- post nativo;
- newsletter micro;
- Kickstarter update futuro.
No publicar todas: preservar sorpresa.

## 5. MÚSICA / CIELO Y DESCENSO
Estado: PROTOTYPE → CQC.
Fortaleza: ya produce identidad fuera del juego.
Gaps:
- derechos/condiciones de generación;
- CQC musical;
- metadata/provenance;
- portada y descriptions;
- estrategia de canal/playlists.
Acción: tras verificar derechos, primer piloto DD completo en YouTube/YouTube Music; Spotify sólo vía distribuidor cuando colección tenga suficiente consistencia.

## 6. PRE-GAME / SEPARACIÓN
Estado: KEEP / PRIVATE.
Razón: todavía está en PRE50 humano.
DD regla: no convertirlo en trailer promesa antes de saber si funciona.
Uso permitido: pequeños teasers abstractos que no congelen diseño.

## 7. PLAYTEST + JOTFORM
Estado: KEEP.
Rol: investigación, no descubrimiento.
Acción: mantener Jotform como tubería; fachada ISL delante.

## 8. VELARIA
Estado: KEEP / DEFER PUBLIC RELEASE.

- soundtrack cue;
- postcard;
- mechanic clip;
- lore entry.
Bloqueo: PC-40 todavía pendiente.

## 9. MOLINO POLL
Estado: KEEP AS RESEARCH.
Gap: una encuesta pública no equivale a prueba de mercado.
Acción: separar voto estético de intención real (wishlist/demo/play).

## 10. NETLIFY PUBLIC
Estado: TUNE PRIORITY.
Necesita:
- sitemap.xml;
- robots.txt coherente;
- canonical URLs;
- OpenGraph/Twitter cards;
- JSON-LD SoftwareApplication/VideoGame/MusicRecording cuando corresponda;
- titles/descriptions únicos;
- image alt/captions;
- landing pública simple;
- enlaces internos hacia contenido público;
- Search Console cuando la landing esté estable.
No indexar zonas internas/experimentales por accidente.

## 11. GITHUB
Estado: KEEP + TUNE.
Rol: verdad técnica y evidencia.
No usar como landing de jugador.
Acción: README público limpio, sin secretos/ruido operacional; enlaces canónicos.

## 12. STEAM
Estado: DEFER.
No abrir page sólo por acumular wishlist si todavía promete una identidad visual/jugable inestable.
Preparar store capsule bible ahora; publicar cuando material represente el producto.

## 13. ITCH.IO
Estado: PROTOTYPE.
Buen hogar para labs/demos con framing.
No subir build débil que confunda identidad.

## 14. DISCORD
Estado: DEFER LIGHT.
Crear sólo cuando tengamos cadencia: cápsula semanal, build/playtest o música/lore.

## 15. EMAIL
Estado: MISSING / HIGH PRIORITY.
Razón: audiencia portable antes de crowdfunding/Steam.
Acción futura inmediata tras landing pública estable:
- waitlist simple;
- consentimiento claro;
- exportable;
- una cadencia baja y cuidada.

## 16. REDDIT
Estado: PROTOTYPE.
No crear "cuenta de promoción ISL" como megáfono.
Usar observación → contribución → feedback → publicación nativa.

## 17. KICKSTARTER / CROWDFUNDING
Estado: DEFER BUT DESIGN NOW.
No campaña hasta vertical slice + audiencia + presupuesto + rewards.
