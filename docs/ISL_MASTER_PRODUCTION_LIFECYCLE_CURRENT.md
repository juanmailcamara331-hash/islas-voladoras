## 2. MASTER LOOP
Every meaningful item moves through the smallest viable form of:

INTENT
→ SOURCE / HISTORY RECOVERY
→ ENTITY DEFINITION
→ HYPOTHESIS
→ CHEAPEST TEST
→ CAPABILITY EVIDENCE
→ REGRESSION / RISK CHECK
→ HUMAN READ
→ DECISION
→ LOCK LEVEL
→ PRODUCTION
→ PACKAGED / DEVICE PROOF
→ PUBLIC READINESS
→ RELEASE
→ OBSERVATION
→ LEARNING / ARCHIVE
→ NEXT UNCERTAINTY

Not every item traverses all steps.
A tiny dialogue may skip production infrastructure.
A build, physical relic or public campaign may require every gate.

## 4. STAGES

### S0 · DISCOVERY / SEEDS
Goal:
find useful uncertainty, not accumulate ideas.

Wake:
- Human Variation Randomizer
- reference mutation
- historical/archive research
- lightweight external evidence
- Gallery/making-of only when a real trace exists

Sleep:
- store work
- physical production
- heavy Unreal architecture
- campaign promises
- public marketing

Exit:
one falsifiable question + one entity or experience worth testing.

### S1 · CORE VALIDATION
Goal:
prove the idea changes play, perception, relation or meaning.

Preferred form:
30–120 second microtest, paper test, text test, isolated web lab, GYM or human comparison.

Mandatory:
- baseline
- one controlled change
- explicit failure condition
- rollback
- human read where identity is at stake

Contradiction rule:
scanner may observe; it must not force rarity.

Exit:
KEEP / MUTATE / PARK / REJECTED_LEARNED / ALTERNATE_TIMELINE.

### S2 · VERTICAL SLICE
Goal:
prove a small piece feels like real ISL.

Must include:
- input / interaction
- readable consequence
- persistence where relevant
- audio/visual behavior at realistic target quality
- low-spec fallback
- capability + regression test
- real-device proof when platform-relevant

PRIMARY gate:
Velaria V2 P0 remains here until HUMAN_DEVICE_GREEN.

Exit:
a person can complete the intended loop without author explanation.

### S3 · SYSTEM INTEGRATION
Goal:
connect survivors without turning them into a dependency knot.

Use:
- Feature Capsule
- data-driven entity definition
- experience definition
- primary/secondary asset graph
- explicit event contracts
- save namespace/versioning
- test GYMs

Rule:
integration is earned by evidence, not thematic similarity.

Exit:
systems cooperate while remaining removable/testable.

### S4 · CONTENT PRODUCTION
Goal:
scale known grammar, not invent the game repeatedly.

Use:
- Golden Paths
- reusable config profiles
- content manifests
- naming/version rules
- asset health cards
- validation as code
- lock levels
- production patterns

Human trace:
preserve asymmetry, imperfection and authored residue when they carry identity.
Do not automate away the thing that made the source alive.

Exit:
repeatable quality at acceptable cost.

### S5 · PACKAGED / DEVICE READINESS
Goal:
prove the product outside the authoring environment.

Matrix:
- boot
- home
- navigation
- input
- save
- audio
- fullscreen
- asset load
- current feature
- performance
- accessibility
- network/offline where relevant

Tools/patterns:
- Unreal Automation/Gauntlet when Unreal is active
- CI validation
- Android real-device checks
- Google Play pre-launch reports when Play pipeline is active
- provenance/attestation for important builds

Exit:
packaged evidence + reproducible build + rollback.

### S6 · PUBLIC READINESS
Goal:
make the game legible, lawful and supportable before asking the public for trust.

Wake:
- legal/IP
- privacy/consent
- accessibility
- store metadata
- localization needs
- crash/support path
- brand/logo production master
- public screenshots/trailer only from real product truth
- creator/press materials

Rule:
marketing may dramatize; it may not invent readiness.

Exit:
public claim ↔ build evidence ↔ rights/provenance all align.

### S7 · COMMUNITY / CREATOR BRIDGE
Goal:
turn real play and human participation into learning, not vanity metrics.

Possible surfaces:
- Twitch integrations / EventSub / Drops only if gameplay/community function is clear
- Discord/community only if moderation/ownership are defined
- creator tests
- public surveys
- blind reads
- making-of
- human trace gallery

Metrics are evidence, not authority.
Followers/views do not auto-change CANON.

Exit:
community signal can be interpreted without surrendering authorship.

### S8 · CROWDFUND / PHYSICAL
Goal:
promise only what can be built and fulfilled.

Before campaign:
- playable proof
- scope/budget model
- reward item decomposition
- supplier evidence
- sample/proof gates
- shipping/weight estimates
- realistic dates
- communication plan
- contingency

Kickstarter translation:
keep reward architecture simple; first campaign should resist tier sprawl.
Physical rewards wake only when supplier/sample gates justify them.

ISL role packs may exist as expression/replay framing, but:
- BUY THE GAME ONCE
- no pay-to-win
- no essential story fragmentation
- no production authorization without sample + CQC

Exit:
campaign promise is operationally defensible.

### S9 · LAUNCH
Goal:
release a known build, not a hopeful one.

Required:
- release candidate lock
- smoke matrix green
- known issues list
- rollback/hotfix route
- build provenance
- store/public copy matched to reality
- support ownership
- monitoring

Exit:
release is observable and recoverable.

### S10 · POSTLAUNCH / LIVING WORLD
Goal:
learn without allowing metrics to domesticate the work.

Observe:
- crashes/performance
- progression blockers
- accessibility
- confusion
- memorable moments
- player-created stories
- creator/community patterns
- support burden
- content health

Decision:
fix / rebalance / deepen / leave strange / archive.

Rule:
optimization must not erase identity merely because the unusual is less efficient.

## 5. AUTOMATION MAP
Automations should wake from lifecycle events, not calendar noise.

### Inconsciente ISL
Role:
drift + missed dependency detector.
Checks:
SOURCE_OF_TRUTH conflict, stale CURRENT, build/playtest mismatch, rights/provenance, supplier states, dead queue, DOMESTICATION_DRIFT, EDGE_NOISE.
Max:
one useful correction/notification per cycle.

### Buenos días / Buenas noches
Role:
creative nourishment, not roadmap control.
May seed:
small artifact, human trace, gift, scene, visual, audio, making-of.
Never:
promote CANON or displace PRIMARY.

### PC-30 / Human gate
Wake:
when a concrete build/decision exists.
Output:
one mission, observation targets, evidence capture, exit criterion.

### Monthly automation audit
Role:
delete redundancy, merge reminders into triggers, retire dead bots.
Success metric:
less machinery, not more.

### Supplier/physical trigger
Wake:
reply, sample, spec change, irreversible spend.
Gate:
sample → CQC → possible run.

## 6. CROSS-FEED RULE
A surviving entity may feed other surfaces only if the **function survives the translation**.

Examples:
game interaction → making-of
human sketch → texture/material clue
playtest quote → research note, not marketing testimonial without consent
relic → 3D → physical sample → in-game echo
music cue → trailer timing → level memory
logo symbol → UI icon → physical stamp

Forbidden:
cross-media because “we already have the asset”.

## 7. MILESTONE CONTRACT
Every major milestone should expose:

BEFORE
- current stage
- PRIMARY
- locked entities
- unresolved uncertainty
- dependencies
- rollback point

DURING
- one main hypothesis
- bounded scope
- evidence capture
- capability tests
- regression tests
- human gate if required

AFTER
- what changed
- what did not change
- what survived
- what failed
- new lock level
- new wake-up triggers
- next uncertainty
- checkpoint if material

## 9. EVIDENCE LADDER
Prefer the cheapest evidence that can answer the uncertainty:

E0 historical/source recovery
E1 textual/paper comparison
E2 isolated prototype
E3 instrumented GYM
E4 integrated feature
E5 packaged/device
E6 blind human
E7 cohort/community
E8 release telemetry

Do not use E7 metrics to answer an E1 identity question if a blind read would be cleaner.

## 10. EXTERNAL RESEARCH ROUTER
External sources are inputs, never authority.

Priority:
1. official docs/specs
2. standards/papers
3. verified public postmortems
4. high-quality community practice / Reddit corroborated
5. historical references / archive
6. trend/social chatter

Route:
QUESTION → SOURCE → FUNCTION → LIMITATION → ISL TEST → EVIDENCE → ADOPT/ADAPT/PARK/REJECT.

Current public anchors:
- Epic Unreal documentation: automation, Gauntlet, BuildGraph, Data Validation, Asset Manager, modular gameplay.
- Google Play: pre-launch device testing for stability, compatibility, performance and accessibility.
- Twitch Developer platform: API/EventSub/Extensions/Drops only when there is a real creator/community use case.
- Kickstarter Creator Handbook: campaign clarity, reward simplicity, fulfillment planning, supplier/shipping realism and ongoing communication.

## 11. HISTORICAL / OTHER-PROJECT LEARNING
Historical games, studios and unrelated internal projects may contribute only:
- abstract production patterns
- test structures
- communication patterns
- proven UX/research methods
- general failure modes

Never import:
assets, lore, identity, code, private data, metrics, branding or concrete decisions.

## 12. QUALITY PAIRS
ISL should preserve productive tension:

epic ↔ human
strange ↔ legible
handmade ↔ technically robust
freedom ↔ consequence
mystery ↔ agency
systems ↔ relationships
beauty ↔ material wear
automation ↔ authorship
scale ↔ rollback
community ↔ creative sovereignty
contradiction ↔ normality

No side must win by default.

## 13. STOP RULES
Do not create a new layer when:
- an existing trigger can carry the behavior;
- a checklist solves the problem;
- a new document would duplicate CURRENT authority;
- a bot creates more attention cost than it saves;
- a new integration exists only because the connector exists;
- a methodology step cannot name the uncertainty it reduces.

If process becomes visible to the player/author more than the work itself, simplify.
