## 1. BUENOS DÍAS ISL
Objetivo:
abrir el día con una pieza pequeña pero memorable.

Prompt base:
Da los buenos días con un regalo o impulso creativo de ISLAS VOLADORAS / ISL basado en el trabajo reciente. Aplica Automation Quality Layer + Human Variation Randomizer. Selecciona silenciosamente PROFILE, número de calas, output family, destino y contradicción opcional. Evita repetir medio, estructura, destino y perfil recientes.

Puede entregar:
imagen/postal/keyframe; vídeo Gemini; prompt Midjourney; Meshy/3D; música/audio; físico/mockup; microescena; UI/cuarta pared; Easter egg; making-of; código/microinteracción; experimento neuroperceptivo; dossier/teaser; worldbuilding funcional.

Cruzar referencias externas sólo mediante FUNCIÓN → CONTRASTE → MUTACIÓN ISL.

Si una herramienta externa mejora el regalo:
entregar prompt listo + una sola línea de uso.

Si el output es significativo:
Event Reflex Loop → persistencia mínima → return PRIMARY.

No CANON automático.
No productividad disfrazada.
Si no hay una pieza que merezca la pena, saludo cálido breve.

## 2. BUENAS NOCHES ISL
Objetivo:
cerrar el día con una pieza que deje buen sabor de boca.

Prompt base:
Cierra el día de ISL usando Automation Quality Layer + Human Variation Randomizer. Basa la pieza en el trabajo real de las últimas sesiones. Alterna formatos y destinos. Máximo una pieza principal + una acción agradable opcional.

Puede ser:
postal nocturna, microescena, audio, vídeo, 3D, objeto físico, código pequeño, Easter egg, making-of, cuarta pared, regalo para padre/Carrillo/colegas, detalle de mundo o teaser.

No repetir fórmula de noches recientes.
Si hay artefacto significativo:
persistir/enlazar/provenance mínimo.
No CANON automático.
Si no hay nada que merezca cierre:
buenas noches breve.

## 3. INCONSCIENTE ISL
Objetivo:
detectar drift y cabos sueltos sin molestar.

Prompt base:
Revisa trabajo reciente aplicando Orchestrator + Event Router + Post-Action Commit Hook + Watchdog + Automation Quality Layer.

Detecta únicamente drift real:
- assets sin registrar;
- huellas sin enlace;
- CURRENT/checkpoints desactualizados;
- provenance ausente;
- duplicados/conflictos SOURCE_OF_TRUTH;
- supplier/build/playtest states no reflejados;
- conectores sin función;
- lane temporal desplazando PRIMARY.

Revisa Gmail para respuestas nuevas de proveedores del Ancla.
Notificar sólo información útil:
coste, muestra, tooling, límites, plazo, siguiente acción.

Máximo UNA corrección reversible.
Si todo está coherente y no hay correo relevante:
no notificar.

## 4. PUNTO CONTROL ISL PC-30
Objetivo:
resolver decisiones que bloquean producción.

Prompt base:
Revisa decisiones relevantes mediante:
TESIS
→ ANTÍTESIS
→ segunda IA si procede
→ papers/precedentes si reducen incertidumbre
→ desacuerdos
→ experimento mínimo
→ confirmación humana.

No enumerar por enumerar.
Sintetizar conflicto + evidencia + mínima acción de desbloqueo.

Si no hay decisión relevante:
usar el bloque para Velaria / vertical slice.

No expandir scope.
No CANON automático.

## 5. AUDITAR AUTOMATIZACIONES ISL
Objetivo:
reducir burocracia y hacer más inteligente el sistema.

Prompt base:
Audita automatizaciones, recordatorios, conectores y procesos recurrentes/recursivos/dialécticos de ISL.

Buscar:
- redundancia;
- solapamiento;
- tarea obsoleta;
- loop que debería ser event trigger;
- recordatorio que debe consolidarse;
- conector sin valor;
- revisión que puede convertirse en hook;
- oportunidad de hacer una automatización más creativa y reutilizable.

Puede consultar metodología abstracta generalizada de otros proyectos, pero jamás importar identidad/assets/lore/código/datos/decisiones concretas.

Cuando reduzca incertidumbre:
docs oficiales, Unreal docs, Discord docs, Google/SEO, archive.org, Reddit corroborado, papers.

Salida máxima:
UNA simplificación/mejora reversible.

## 6. TESTER / HUMAN DEVICE
Estado:
no necesita automation dedicada si ya está absorbida por otros flows.

Trigger recomendado:
cuando HUMAN_DEVICE_GREEN / playtest evidence esté realmente pendiente y una build concreta exista.

Prompt funcional:
preparar una única misión humana con objetivo, build, qué observar, 3–8 preguntas adaptadas, criterio de salida y captura de evidencia.
No feedback→CANON automático.

## 7. SUPPLIER / PHYSICAL
Trigger:
respuesta de proveedor, sample disponible, cambio de spec o decisión irreversible.

Prompt funcional:
comparar sólo dimensiones reales:
viabilidad, proceso, coste, tooling, límites, muestra, lead time, shipping, calidad esperada, riesgos.
No recomendar producción grande antes de sample + physical CQC.

## 8. GENERATIVE GIFT MULTILAYER
Trigger:
regalo creativo de alto potencial.

Prompt funcional:
puede producir 2–5 calas:
1) pieza;
2) destino;
3) prompt/herramienta;
4) integración ISL;
5) cruce de medio/capa.

Posibles cruces:
making-of + Easter egg + cuarta pared + físico + vídeo + audio + 3D + futura escena.

Regla:
una pieza puede alimentar varias superficies sólo si su función sigue viva.

## 9. REFERENCE / CREATIVE MUTATION
Trigger:
cuando una referencia externa pueda mejorar una pieza real.

Prompt funcional:
identificar función;
identificar riesgo de collage/copia;
contrastar con ISL;
mutar;
producir experimento mínimo.

No imitar estilos de creadores vivos de forma directa.
Usar rasgos de alto nivel, historia del arte, géneros, materiales, composición, tono o técnicas.
