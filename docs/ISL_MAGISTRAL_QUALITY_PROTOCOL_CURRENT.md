# ISL_MAGISTRAL_QUALITY_PROTOCOL_CURRENT

Estado: PROVISIONAL FUERTE · TRANSVERSAL · OBLIGATORIO
Proyecto: ISLAS VOLADORAS / ISL
Fecha: 2026-09-21

## 0. PROPÓSITO
Este protocolo existe para preservar a la vez:
- calidad alta;
- vaguedad creativa fértil;
- coherencia sistémica;
- velocidad de producción;
- alma/autoria humana;
- capacidad de rollback;
- evidencia real antes de fijar.

No convierte ISL en burocracia. Si una vuelta metodológica no cambia una decisión, no descubre un riesgo ni mejora perceptiblemente el resultado, se detiene.

## 1. DISPARADOR OBLIGATORIO
Este protocolo SALTA antes de cualquier cambio que afecte:
- gameplay;
- UX/UI;
- mundo/islas/escenas;
- criaturas/personajes;
- argumento;
- cronología/líneas temporales;
- hitos narrativos;
- relaciones/tripulación;
- música/audio;
- visual/3D/assets;
- IA generativa;
- web/app/PS4/Android;
- presentación a colegas/inversores;
- encuestas/playtests;
- publicación/public-private boundary.

## 2. TARJETA MAGISTRAL MÍNIMA
Antes de construir:
1. PROMESA — ¿qué debe sentir/entender el humano?
2. ATENCIÓN — ¿qué única cosa debe mirar/pensar primero?
3. ACCIÓN — ¿qué hace físicamente?
4. FEEDBACK — ¿cómo sabe que su acción tuvo efecto?
5. SORPRESA — ¿qué pequeña desviación evita que sea genérico?
6. Δ — ¿qué transformación perceptible queda después?
7. INTEGRACIÓN — ¿con qué máximo 1–3 sistemas ya existentes conecta?
8. REGRESIÓN — ¿qué cosas ya buenas podría romper?
9. EVIDENCIA — ¿qué conducta humana demostraría que funcionó?
10. STOP — ¿qué condición nos impide seguir perfeccionando por inercia?

## 3. Q_PLAY / Q_EXPERIENCE
Operador provisional de decisión, NO puntuación CANON:

Q = min(C, A, F, D, R)

C = claridad
A = agencia
F = feel / respuesta sensorial
D = deseo de continuar o recordar
R = robustez / ausencia de regresiones

La calidad fuerte no se obtiene compensando una debilidad grave con decoración.
Si una dimensión es débil, primero se arregla esa dimensión.

## 4. CQC-R
CONSTRUIR → CQC-1 → CORREGIR → CRUZAR → CQC-2 → EVIDENCIA HUMANA → CERRAR / MUTAR / PARK / KILL

Niveles:
- objeto: ¿funciona por sí mismo?
- relaciones: ¿qué sinergias ×, Δ o interferencias aparecen?
- método: ¿lo aprendido cambia una regla del propio proceso?

## 5. 1–3–∞
- una prueba mínima;
- máximo tres conexiones iniciales;
- potencial de expansión sólo después de demostrar valor.

Aplicable a:
mecánicas, escenas, personajes, música, cronología, assets, herramientas, integraciones IA.

## 6. RAMAS PARALELAS DE CALIDAD
Por bloque activo puede haber:

### PRIMARY LANE
Única línea que puede cambiar el producto/hito activo.

### QUALITY LANES
Máximo 2–4, acotadas:
- VISUAL / Midjourney / Gemini Image / arte;
- 3D / Meshy;
- AUDIO / Gemini Music u otra herramienta;
- RESEARCH / papers, docs, archive.org, comunidad;
- PERFORMANCE / device/runtime;
- PRESENTATION / print/inversores.

Una quality lane puede:
- preparar candidatos;
- eliminar un cuello de botella;
- crear comparativas;
- subir fidelidad;
- descubrir riesgos.

No puede:
- ascender a CANON;
- cambiar roadmap;
- imponer estética;
- introducir sistema núcleo nuevo;
- mezclar proyectos;
- retrasar el hito principal.

## 7. IA / HERRAMIENTAS EXTERNAS
Pipeline obligatorio:
INTENCIÓN → PROMPT → 2–4 CANDIDATOS → PROVENANCE → COMPARATIVA → MUTATE / PARK / KILL → CQC → HUMAN GATE → MASTER → RUNTIME

Reglas:
- MASTER != RUNTIME.
- generar no equivale a adoptar.
- no regenerar activos buenos sin una hipótesis concreta.
- registrar herramienta/modelo/fecha/referencia/uso.
- ninguna IA decide CANON.

Gemini:
- texto/ideas/variantes/música cuando corresponda;
- contraste y expansión controlada.

Midjourney:
- exploración visual y candidatos;
- no identidad definitiva por mayoría de imágenes.

Meshy:
- 3D desde referencias consistentes;
- multiview QA antes;
- RAW/MASTER y runtime separados.

Otros proveedores:
- sólo detrás de adapters/protocolos cuando aportan algo real.

## 8. REFERENCIAS CULTURALES / AUTORALES
Regla universal:
REFERENCIA → FUNCIÓN → CONTRASTE → REINTERPRETACIÓN → LENGUAJE ISL PROPIO

Nunca:
- copiar apariencia;
- copiar voz;
- copiar personaje;
- copiar chiste;
- copiar trama;
- copiar composición reconocible.

### Terry Pratchett — funciones ISL
- humor que revela verdad;
- sátira que pincha sistemas y autoridad;
- personajes secundarios con dignidad;
- absurdo gobernado por reglas internas;
- ideas filosóficas aterrizadas en escenas comprensibles;
- ternura debajo del cinismo;
- coherencia acumulativa del mundo;
- callbacks y consecuencias que hacen sentir historia vivida.

Test Pratchett-función:
¿la rareza hace el mundo más humano/comprensible o sólo más extravagante?

## 9. NARRATIVA / CRONOLOGÍA / HITOS
Toda nueva pieza debe declarar:
- antes;
- ahora;
- después;
- qué recuerda el mundo;
- qué cambia en personaje/vínculo/mundo;
- qué contradicción abre o resuelve;
- qué payoff prepara;
- si recontextualiza algo anterior.

No añadir lore que no:
- cambie lectura;
- cambie decisión;
- cambie vínculo;
- prepare payoff;
- o aumente identidad memorable.

## 10. EXPERIENCIA EXTERNA
Para colegas/padre/inversores:
- no mostrar herramientas internas primero;
- no enseñar Cartógrafo/Command Center como “juego”;
- una promesa;
- una imagen/escena aspiracional claramente etiquetada;
- una prueba jugable;
- una progresión visible hacia el producto completo;
- lenguaje humano, preciso y no técnico.

## 11. REGRESIÓN TRANSVERSAL
Antes de cerrar:
- revisar bugs conocidos;
- revisar navegación;
- revisar cache/versionado;
- revisar móvil/orientación;
- revisar audio/fullscreen;
- revisar save;
- revisar privacidad;
- revisar que ninguna quality lane haya cambiado espíritu o scope sin decisión.

## 12. PRINCIPIO
“No escatimamos en calidad. Escatimamos ferozmente en desperdicio.”

Calidad ISL = precisión suficiente para sostener libertad creativa.


## 13. CHECKFRAME / PRESENTACIÓN HUMANA · 2026-09-22
Cuando una pieza tenga estado, rumbo o trabajo pendiente visible:
usar preferentemente:
[✓] HECHO · [ ] AHORA · [ ] DESPUÉS.

No usarlo dentro del gameplay si rompe inmersión.
Sí usarlo en:
Rumbo · briefs · playtests · handoffs · PDFs · Carrillo · presentación · revisión.

Regla visual:
IMAGEN / CONTENIDO → DECISIÓN / ACCIÓN → DETALLE TÉCNICO.

El detalle técnico nunca debe competir con la pieza principal en una superficie humana.


## 14. PREPARACIÓN MAGISTRAL DE BALAS CREATIVAS / VISUALES · 2026-09-23

Esta sección NO crea un órgano nuevo. Formaliza la manera de preparar balas dentro del Quality Router existente.

Regla:
**NO IMPROVISAR BALAS. NO PROMPT MAGISTRAL = NO BALA.**

Orden operativo por defecto para una bala creativa importante:

**RECOVER → PREFLIGHT → CRUCE METODOLÓGICO MÍNIMO → PESOS → RANDOMIZER → CONTRASTE/FALSADORES → FICHA DE BALA → PROMPT MAGISTRAL A–J → HUMAN GATE → GENERACIÓN → LECTURA → DECISIÓN → RETURN HOME**

### 14.1 RECOVER
Antes de imaginar:
- recuperar PRIMARY;
- SOURCE_OF_TRUTH;
- autoridad humana vigente;
- binarios/referencias exactas si existen;
- historia y decisiones previas;
- riesgos de recency/authority drift;
- SAFE HARBOR;
- estado real del órgano/pieza.

Si aparece una referencia humana exacta durante RECOVER:
**detener la deriva, elevarla a SOURCE_OF_TRUTH visual según su lock level y derivar desde ella.**

### 14.2 PREFLIGHT
Declarar:
- SUBJECT;
- OPERATION;
- SOURCE_OF_TRUTH;
- estado/gate;
- 1–4 capas/metodologías realmente relevantes;
- qué NO se puede tocar.

Estados útiles:
PASS / NEED_RECOVERY / AUTHORITY_DRIFT / HUMAN_GATE / BLOCKED.

### 14.3 CRUCE METODOLÓGICO MÍNIMO
Cruzar sólo lo que reduzca incertidumbre o riesgo.
Candidatos frecuentes:
- Meta-Layer Orchestrator;
- Organism Radiography;
- Authority Pruning Matrix;
- Creative Weights Calibration;
- Human Variation Randomizer;
- Recursive Dialectic Quality Router;
- Reference Function & Coherence Protocol;
- Context Hygiene;
- Impossible Physics / Human Consequence cuando aplique;
- Cross-Domain Methods Atlas sólo cuando aporte evidencia o mecanismo real.

No activar capas por decoración metodológica.

### 14.4 PESOS
Elegir normalmente **2–4 ejes**.
Ponderar HIGH / MEDIUM / LOW.
La bala debe saber qué sacrificar antes de generar.

### 14.5 RANDOMIZER
Perturbar normalmente sólo **1–2 variables**.
El dado propone; nunca decide CANON.
Si la perturbación cambia la gramática protegida, se descarta.

### 14.6 CONTRASTE Y FALSADORES
Antes del prompt final:
- declarar BASELINE;
- declarar MUTACIÓN;
- declarar anti-referencias o referencias por función;
- definir 3–8 falsadores concretos.

Un resultado bello puede ser FAIL si:
- pierde función;
- rompe autoridad;
- sólo añade decoración;
- depende de mockup/contexto para funcionar;
- reduce claridad;
- deriva hacia referencias reconocibles;
- parece “IA genérica”;
- domestica o exagera la pieza sin necesidad.

### 14.7 FICHA DE BALA
Debe incluir como mínimo:
- ID;
- nombre;
- estado;
- pregunta;
- hipótesis;
- SOURCE_OF_TRUTH;
- baseline;
- mutación;
- capas;
- pesos;
- randomizer;
- referencia principal por función;
- referencia lateral o NONE;
- riesgos;
- éxito;
- falsadores;
- RETURN HOME.

### 14.8 PROMPT MAGISTRAL A–J
Para balas visuales/importantes usar estructura amplia cuando mejore precisión:

A · IDENTITY / STATE  
B · QUESTION / HYPOTHESIS  
C · SOURCE_OF_TRUTH / LOCKS  
D · FUNCTION / ORGANISM  
E · FORM / COMPOSITION  
F · MATERIAL / CAUSALITY  
G · CREATIVE WEIGHTS  
H · RANDOMIZER / DIALECTIC  
I · ANTI-ERROR / FALSIFIERS / REFERENCE DISTANCE  
J · EXPECTED OUTPUT / HUMAN READ / RETURN HOME

No rellenar por inercia. Cada sección debe cambiar una decisión, proteger una autoridad o mejorar la lectura.

### 14.9 HUMAN GATE ANTES DE GENERAR
Si el humano ha fijado una orden de disparo explícita, no generar antes de ella.
Ejemplos:
DISPARA / PUM / LÁNZALA / GENERA / APROBADA.

### 14.10 DESPUÉS DE GENERAR
La imagen es **SENSOR**, no autoridad.
Leer por:
- olor ISL;
- corazón;
- nervio;
- causalidad;
- jugabilidad/función;
- memoria;
- humanidad;
- distancia de referencias;
- ruido;
- replay/reutilización cuando aplique;
- regresión contra baseline.

Decisión:
KEEP / MUTATE / PARK / KILL / REROLL.

Una imagen espectacular NO asciende automáticamente a CANON.

### 14.11 RETURN HOME
Cerrar cada bala declarando:
- qué sigue intacto;
- qué no ha sido promovido;
- qué autoridad manda;
- qué necesita comparación humana;
- qué binario/provenance debe registrarse;
- cómo volver a SAFE HARBOR.

Principio:
**EL DADO PROPONE. LA METODOLOGÍA TENSIONA. LA IMAGEN REVELA. EL HUMANO DECIDE. ISL RECUERDA.**


## 15. GUIDED PLAYFLOW / HUD QUALITY INVARIANT · 2026-09-23
For every world-space, combat-space or navigation-facing milestone, add these quality questions:

- Can the player infer the next useful direction without a mission arrow?
- Is the HUD smaller than the world-information layer?
- Does wandering produce discovery rather than empty traversal?
- Is the macro path authored and legible?
- Are locked regions explained diegetically?
- Could a wind/light/sound/landmark cue replace a UI element?
- Does the space remain readable when archetype/Huella/replay variants alter local content?
- Is the experience guided without feeling corridor-like?
- Is it semi-open without becoming checklist-open-world?
- If the HUD vanished for 30 seconds, would the scene still communicate enough?

Reference authority:
docs/ISL_GUIDED_WORLD_HUD_AND_PLAYFLOW_DIRECTION_CURRENT.md

Hard drift warnings:
PERSISTENT_MISSION_MARKER_BY_DEFAULT
MINIMAP_DEPENDENCY
CHECKLIST_OPEN_WORLD_DRIFT
ARBITRARY_INVISIBLE_WALL
HUD_EXPLAINS_WORLD
LOCAL_VARIATION_BREAKS_MACRO_RUMBO

Correct in that order before adding new systems.


## 16. ROBUST QUALITY READING · 2026-09-23
When enough human/playtest evidence exists, complement Q = min(C,A,F,D,R) with:
- Q_MED = median(C,A,F,D,R)
- Q_STABLE = median(last N Q_MED) - MAD(last N Q_MED)

Purpose:
avoid a beautiful outlier hiding a weak dimension and avoid one noisy session defining the project.

No score replaces human reading.
No score promotes CANON.
If sample size is tiny, show qualitative bands instead of fake precision.
